# 01 · 平台核心详细设计（目录 / 播放器 / 排行榜 / 管理台 / 遥测）

> 状态：设计稿（M1–M2 实施依据）
> 约束来源：兄弟工程同栈约定（Java 21 + Boot 3.4.5 + Modulith / Vue3+Vite+TS / JPA+Flyway / Redis Streams / sysou-manage 中心身份）；游戏包与运行时协议见 `02` 文档。

---

## 1. 目标 / 非目标

**M1**：目录页 + 详情页（iframe 试玩）+ 管理台（上传/校验/发布/下架/回滚）+ 部署上线。
**M2**：sysou-manage 登录 + 排行榜（全服/周）+ 成就。
**M3**：遥测最小集（PV/开始/时长/分数分布）+ **云存档（P7：账号绑定、跨设备；`user_save` 表 + §5.2 存档 API，游戏侧桥接 ~40 行，02 文档 §4.4）**。

非目标：UGC、支付、多语言（先中文，字段预留 `lang`）、原生 App、CDN（预留演进点）。

## 2. 后端架构（Spring Modulith 模块化单体）

```
gamevault.jar（127.0.0.1:8094，systemd 部署，参照 ../EasyPCB/deploy/easypcb.service 形态）
├── api           // 认证过滤（JWKS 验签）、全局异常、限流入口、OpenAPI
├── catalog       // 游戏目录与详情（game / game_version 查询、封面、标签）
├── player        // 试玩会话：play-session 创建/心跳/结束（M3 起喂遥测；M1 只埋点）
├── leaderboard   // 分数提交（校验+幂等）、榜单读（ZSET）、成就判定/发放
├── achievement   // 成就定义、解锁记录、条件求值
├── telemetry     // /api/telemetry 批量收事件 → Redis → 每日 Job 聚合落库（M3）
├── admin         // 游戏包上传(异步 Job)/校验/发布/下架/回滚、管理端查询
└── common        // Redis 封装、Redis Streams Job 框架（消费组+死信+幂等，复用兄弟工程模式）、
                    // 配置、Flyway 迁移、审计日志
```

Modulith 纪律（与兄弟工程一致）：模块间只经公共 API（`…Api` 接口）调用，模块内部 Bean 不跨模块注入；
`@ApplicationModule` 边界由 ArchUnit 测试守护（`ModulithTest`）。

### 2.1 异步 Job（Redis Streams，兄弟工程同款）

| Job | 触发 | 说明 |
|---|---|---|
| `GAME_PACKAGE_PROCESS` | 管理台上传 zip 后入流 | 校验 → 解压 → 版本目录落位 → 写 `game_version` 状态；幂等键 = `packageId`；死信流 + 管理台「重试/放弃」 |
| `SCORE_SETTLE`（M2） | 定时 5 分钟 | 把 Redis ZSET 分数增量落 `user_score` 表（异步落库，提交路径只写 Redis） |
| `TELEMETRY_AGG`（M3） | 每日 00:10 | Redis 计数 key 聚合 → `play_event_daily` 落库，清当日 key |
| `LEADERBOARD_WEEK_RESET`（M2） | 每周一 00:00 | 周榜 key 轮换归档 |

消费组 `gamevault`；死信流 `gamevault:dead`；幂等键 `idempotency_key` 落 `job_outbox`（与 Weaveora 同款）。

### 2.2 限流（Redis，禁 ConcurrentHashMap 计数）

| 入口 | 策略（固定窗口/令牌桶均可，Redis `INCR`+TTL 或 `ZSET` 滑窗） |
|---|---|
| `POST /api/scores` | 每用户每游戏 **20 次/10 分钟**；游客禁止 |
| `PUT /api/saves/{gameSlug}` | 每用户每游戏 **60 次/小时**（云存档，M3） |
| `POST /api/telemetry` | 每 IP 120 事件/分钟，单包 ≤ 50 事件 |
| `POST /api/admin/packages` | 每管理员 5 次/小时 |
| `GET /api/games/**` | 无（静态页另有 nginx 缓存） |

## 3. 数据模型（PostgreSQL，独立 db `gamevault`；Flyway 迁移，`ddl-auto=validate`）

```sql
-- V1__init.sql（M1）
CREATE TABLE game (
  id            BIGSERIAL PRIMARY KEY,
  slug          TEXT NOT NULL UNIQUE,          -- 对外标识，URL 用：neon-raid
  title         TEXT NOT NULL,                 -- 霓虹突袭
  subtitle      TEXT,
  engine        TEXT NOT NULL,                 -- phaser-4 | threejs | godot-4.6 | canvas-native
  language      TEXT NOT NULL,                 -- typescript | gdscript
  cover_url     TEXT NOT NULL,                 -- 封面（/game/g/<slug>/cover.png）
  description   TEXT,                          -- 简介（中文）
  tech_notes_url TEXT,                         -- 技术拆解文档链接（P5）
  media           JSONB NOT NULL DEFAULT '{}', -- N0 预留（08 文档 §8）：{"screenshots":[...],"trailer":"...","external_links":[...]}
                                               --   宣传面（截图墙/预告片/外部商店导流链接），M1 起即可用，原生发行前瞻用
  tags          TEXT[],                        -- {'arcade','shooter','2d'}
  status        TEXT NOT NULL DEFAULT 'draft', -- draft | live | disabled
  sort_order    INT NOT NULL DEFAULT 0,
  created_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at    TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE TABLE game_version (
  id            BIGSERIAL PRIMARY KEY,
  game_id       BIGINT NOT NULL REFERENCES game(id),
  version       TEXT NOT NULL,                 -- semver：1.0.0
  manifest      JSONB NOT NULL,                -- 冻结的 manifest.json 副本（02 文档 §3.1）
  entry_url     TEXT NOT NULL,                 -- /game/g/<slug>/1.0.0/index.html
  package_sha256 TEXT NOT NULL,
  size_bytes    BIGINT NOT NULL,
  status        TEXT NOT NULL DEFAULT 'staged',-- staged | live | rolled_back
  published_at  TIMESTAMPTZ,
  created_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
  UNIQUE (game_id, version)
);

-- M2
CREATE TABLE user_score (
  id            BIGSERIAL PRIMARY KEY,
  user_id       BIGINT NOT NULL,               -- sysou-manage 用户 id（中心表，不建本地用户）
  game_slug     TEXT NOT NULL,
  score         BIGINT NOT NULL,
  meta          JSONB NOT NULL DEFAULT '{}',   -- 游戏自定义字段（波次/连击等，schema 由 manifest.scoreSchema 约束）
  client_ts     TIMESTAMPTZ NOT NULL,
  submitted_at  TIMESTAMPTZ NOT NULL DEFAULT now(),
  status        TEXT NOT NULL DEFAULT 'ok',    -- ok | rejected_bounds | flagged
  reject_reason TEXT,
  UNIQUE (id)
);
CREATE INDEX idx_score_board ON user_score (game_slug, submitted_at);

CREATE TABLE achievement_def (
  id            BIGSERIAL PRIMARY KEY,
  game_slug     TEXT NOT NULL,
  code          TEXT NOT NULL,                 -- FIRST_CLEAR | SCORE_10K
  title         TEXT NOT NULL,
  description   TEXT NOT NULL,
  icon_url      TEXT,
  UNIQUE (game_slug, code)
);

CREATE TABLE achievement_grant (
  id            BIGSERIAL PRIMARY KEY,
  user_id       BIGINT NOT NULL,
  game_slug     TEXT NOT NULL,
  achievement_id BIGINT NOT NULL REFERENCES achievement_def(id),
  granted_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
  UNIQUE (user_id, achievement_id)
);

-- M3
CREATE TABLE user_save (
  id             BIGSERIAL PRIMARY KEY,
  user_id        BIGINT NOT NULL,
  game_slug      TEXT NOT NULL,
  slot           TEXT NOT NULL DEFAULT 'default',  -- 存档槽（游戏可多槽，manifest.saves.cloud.slots 声明）
  data           JSONB NOT NULL,                   -- 对平台不透明（opaque）；JSON only，无执行面；≤ 256KB/槽
  schema_version INT NOT NULL DEFAULT 1,           -- 游戏侧存档结构版本（迁移由游戏客户端负责，服务端不感知）
  size_bytes     INT NOT NULL,
  updated_at     TIMESTAMPTZ NOT NULL DEFAULT now(),
  UNIQUE (user_id, game_slug, slot)
);
CREATE INDEX idx_save_user ON user_save (user_id, game_slug);

-- M3
CREATE TABLE play_event_daily (
  id            BIGSERIAL PRIMARY KEY,
  stat_date     DATE NOT NULL,
  game_slug     TEXT NOT NULL,
  pv            BIGINT NOT NULL DEFAULT 0,
  play_started  BIGINT NOT NULL DEFAULT 0,
  play_finished BIGINT NOT NULL DEFAULT 0,
  duration_sec  BIGINT NOT NULL DEFAULT 0,     -- 累计
  score_p50     INT, score_p90 INT,
  UNIQUE (stat_date, game_slug)
);
```

Redis（db3）键规划（全部带 TTL 或可归档）：

| Key | 类型 | 用途 |
|---|---|---|
| `lb:all:<slug>` | ZSET | 全服总榜（member=`<userId>`, value=最高分） |
| `lb:week:<slug>:<yyyyww>` | ZSET | 周榜 |
| `lb:pending:<slug>` | List | 待落库分数队列（SCORE_SETTLE 消费源；也可用 Streams） |
| `limit:<scope>:<key>:<window>` | String | 限流计数（§2.2） |
| `game:meta:<slug>` | String(JSON) | 目录缓存（TTL 10min，写穿失效） |
| `sess:<playSessionId>` | Hash | 试玩会话（M3 遥测用；M1 可省） |

## 5. API 契约（REST，JSON；前缀 `/game/api/`，nginx 剥前缀后到 8094）

> 字段全英文；文案中文。错误封套：`{ "error": { "code": "SCORE_REJECTED", "message": "分数超出合理区间" } }` + HTTP 语义码。

### 5.1 公开（匿名）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/games` | 目录列表（status=live；`?tag=`/`?engine=` 过滤）→ `GameCard[]`（含 live 版本、Top3 分数） |
| GET | `/api/games/{slug}` | 详情（含 `liveVersion.entryUrl`、`scoreSchema`、成就定义、Top10）；响应恒带 `builds[]`（N0 预留，M1–M5 仅 web 一条，原生构建 N1 起填充，08 文档 §5.2/§8） |
| GET | `/api/games/{slug}/leaderboard?scope=all\|week` | 榜单 Top100：`[{rank, userName, score, meta, updatedAt}]`（匿名提交显示昵称占位「游客」——M2 起榜单只收登录分） |
| GET | `/api/health` | 存活探针 |

### 5.2 需登录（中心 JWT，`Authorization: Bearer <jwt>`）

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/scores` | 提交分数：`{ gameSlug, score, meta, clientTs, idempotencyKey }`；
  校验链：限流 → 登录态 → `scoreSchema` 边界 → 时间合理性（`clientTs` 与游戏会话时长自洽）→ 写 Redis 榜 + 落待落库队列 → 返回 `{ rank }`；
  幂等键重复 → 200 返回原结果 |
| GET | `/api/me/scores?gameSlug=` | 我的历史提交 |
| GET | `/api/me/achievements?gameSlug=` | 我的成就 |
| GET | `/api/saves/{gameSlug}?slot=default` | 我的云存档（M3）：`{data, schemaVersion, updatedAt}`；404 = 首次（游戏侧回落本地档/新档） |
| PUT | `/api/saves/{gameSlug}` | 上传云存档（M3）：`{slot, data, schemaVersion, baseUpdatedAt?, force?}`；JSON only + ≤256KB + `manifest.saveSchema` 声明上限校验 + §2.2 限流；`baseUpdatedAt` 不一致且无 `force` → **409**（游戏侧弹「其他设备存档冲突」，由玩家选保本地/取云端）；成功返回服务端 `updatedAt` |
| POST | `/api/telemetry` | `[{type: "play_start"\|"play_end"\|"pv", gameSlug, ts, durMs?, sessionId?}]` ≤50 条/包 |

### 5.3 管理（权限点 `gamevault:admin:*`，中心 RBAC；前端隐藏 + 后端独立校验，双端生效红线）

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/admin/packages` | 上传 zip（multipart，≤100MB）→ 建 `GAME_PACKAGE_PROCESS` Job，返回 `packageId` |
| GET | `/api/admin/packages/{id}` | Job 状态 + 校验报告（结构/大小/manifest/安全扫描逐项） |
| POST | `/api/admin/packages/{id}/publish` | 发布为 live（同游戏旧 live 版本自动 `rolled_back` 保留可再回滚） |
| POST | `/api/admin/games/{slug}/disable` / `:enable` | 下架/上架 |
| POST | `/api/admin/games/{slug}/rollback` | 回滚到指定 version |
| GET | `/api/admin/games` | 管理视角全状态列表（含 draft/disabled） |

**管理台权限点清单**（向 sysou-manage 申请角色 `gamevault_admin` 挂载）：
`gamevault:admin:package`、`gamevault:admin:publish`、`gamevault:admin:game-status`。
普通访客角色 `gamevault_user`：仅 §5.1/5.2。

## 6. 排行榜与成就（M2）

### 6.1 提交校验链（服务端裁决，红线）

1. **限流**（§2.2）→ 超限 429。
2. **登录态**：中心 JWT 验签失败 → 401。
3. **schema 校验**：`score` 为整数且在 `manifest.scoreSchema.range` 内（如霓虹突袭 0–99,999,999）；
   `meta` 字段按 schema 校验（未知字段丢弃并告警）。
4. **时间合理性**：`clientTs` 不早于当前-5min、不晚于当前+2min；该会话最短游戏时长
   （由 `play_session` 心跳估算，M1 简化为「提交时刻 - 会话创建时刻 ≥ 3s」）。
5. **异常检测**：同用户单局分数超过全服 P99×5 → `status=flagged`（不进榜，进人工复核队列
   `admin → flagged scores` 页，人工确认/拒绝）。
6. 通过 → `ZADD lb:all` / `ZADD lb:week` + 入待落库队列 → 返回当前名次。

周榜每周一 00:00 由 `LEADERBOARD_WEEK_RESET` 归档上周 key 并开新 key；总榜只增不删（最高分制）。

### 6.2 成就

- 定义由管理台维护（`achievement_def`），条件为声明式规则（`{"type":"score_gte","value":10000}`、
  `{"type":"game_over","meta":{"clear":true}}`、`{"type":"combo_gte","value":30}`）。
- 求值时机：`POST /api/scores` 成功后同步求值（规则集小，<10 条/游戏）→ 新解锁写
  `achievement_grant` + 响应体带 `unlocked: [...]`，前端弹解锁动画。
- 服务端判定，客户端不可自报（同排行榜红线）。

## 7. 认证与 RBAC（sysou-manage 接入）

- **不自建用户体系**（红线）。后端 `api` 模块实现中心 JWT 校验：
  ES256 / EC P-256，JWKS 从 sysou-manage 端点拉取并缓存（与兄弟工程同款，参照其 `AuthConfig` 模式）；
  权限点从中心 `/me/perm` 语义对齐（本地按权限点鉴权，`gamevault:admin:*`）。
- 角色申请：`gamevault_user`（默认，登录即有）、`gamevault_admin`（手动授予）。
- 游客策略：试玩/看榜不登录；提分与成就必须登录（M2 起）。

**部署事实清单（上线时逐项核对并回填本文）**：
- 后端 systemd：`gamevault.service`（ExecStart=java -jar /opt/gamevault/gamevault.jar，WorkingDirectory=/opt/gamevault，

  （上线前对兄弟前缀抽样 `curl -sI` 确认未受影响）。

## 9. 性能预算

| 项 | 预算 | 手段 |
|---|---|---|
| 平台首屏（首页 HTML+JS+CSS） | gzip 后 JS ≤ 150KB | Vue 路由懒加载；admin 视图独立 chunk |
| 详情页首玩时间（P90，4G 模拟） | ≤ 3s（游戏 D 类）/ ≤ 8s（游戏 A/B 类）/ 有进度条（C 类 ≤ 30MB） | 02 文档：Brotli + 长缓存 + 进度 UI |
| API P95 | 目录/详情 ≤ 150ms（Redis 缓存命中时 ≤ 30ms）；提分 ≤ 100ms | 目录缓存 10min TTL；提分只写 Redis |
| 榜单读取 | ≤ 50ms | ZSET `ZREVRANGE` |
| 单机容量 | 并发试玩 500 iframe（纯静态，nginx 出）；API 500 QPS | 个人站量级富余 10×；超了先加 CDN 再谈扩容 |

## 10. 测试策略

- 单测：`leaderboard` 校验链（边界/限流/幂等/flagged 判定纯函数化）、`admin` manifest 校验器、
  成就规则求值器。

  `/game/g/reflex-rush/...` 200 + COOP/COEP 头 → 匿名提分 401 → 模拟登录提分 200 + 名次。

  （手机）——重点：COOP/COEP 下 iframe 行为、触控、音频自动播放策略。

## 11. M1 模块落地顺序（任务清单）

1. 仓库骨架：`pom.xml`（Modulith 依赖）、模块目录、Flyway V1、`application.yml`（8094、db/redis 配置外置 env）。

6. 部署：`deploy/` 三件套（systemd + nginx conf + smoke.sh）→ 上线 → 回填 §8 部署事实清单。
