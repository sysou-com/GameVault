# 02 · 游戏运行时与发布管线详细设计

> 状态：设计稿。本文是「任何一款游戏如何被平台承载」的唯一真源：包规范、播放器协议、
> COOP/COEP、发布/回滚管线、安全边界。`03..07` 各游戏文档只描述游戏自身，接入部分一律引用本文。

---

## 1. 承载模型（先定边界）

- **游戏 = 纯静态包**（HTML/JS/WASM/音频/图片/字体），平台**永不执行任何服务端游戏代码**。
  Godot 导出的 `.wasm`、Phaser/Three 的 bundle 都只是浏览器里跑的静态文件。
- 游戏包由 nginx 直接从 `/var/www/gamevault/games/` 静态服务（不经 Java 后端，01 文档 §8）。
- 平台与游戏**同源**（都在 `/game/` 下）：
  - 游戏可以直接 `fetch('/game/api/...')` 调平台 API（带玩家浏览器里的中心 JWT，前端注入，见 §4.3）；
  - 同时保留 `postMessage` 协议（§4）作为一等契约 —— 未来游戏包迁到独立 CDN/子域时只改 `entry_url`，
    协议不变（这是预留的 CDN 演进点，Poki/CrazyGames 即此模式）。
- 播放器 = 平台前端 `GameFrame.vue` 里的 `<iframe sandbox="allow-scripts allow-same-origin
  allow-pointer-lock allow-autoplay">`。**不给** `allow-top-navigation`（游戏不能跳走顶层页面）；
  `allow-same-origin` 必须给（游戏要读 localStorage 存档 + 调同源 API）——二者同给时 sandbox
  对同源内容约束有限，真正的隔离边界是「静态目录不可写 + 包内容发布前扫描 + 同源 API 鉴权/限流」，
  这是**受信任自研游戏**的前提；若未来开放第三方上传，本设计整体重审（红线：MVP 不做 UGC）。

## 2. 版本化与目录布局

```
/var/www/gamevault/games/
└── <slug>/
    └── <version>/            # semver，如 1.0.2
        ├── index.html        # 入口（manifest.entry）
        ├── manifest.json     # 必带（§3.1）
        ├── cover.png         # 封面 1280x720（平台卡片用）
        └── ...               # 其他静态资源（音频/图集/wasm/pck）
```

- **不可变版本**：发布后只读；任何变更 = 新版本目录。回滚 = 切 `game_version.status`（不删目录）。
- 版本保留策略：每游戏保留最近 5 个 live 过的版本 + 1 个 live；更早的由管理台「清理」动作显式删除
  （遵守 CLAUDE.md 红线：删除必须列清单 + 确认 + 留恢复路径（zip 备份到 `/var/www/gamevault/archive/`））。
- 目录权限：`/var/www/gamevault/games/` 属 root，nginx 只读访问；后端以专用用户 `gamevault` 运行，
  写权限仅限 `games/` 与 `archive/`（`setfacl`/`chown`，部署脚本固化）。

## 3. 游戏包规范

### 3.1 `manifest.json`（包根，必带）

```jsonc
{
  "schema": "gamevault/manifest@1",
  "game": "reflex-rush",            // 与目录 slug 一致；新游戏由管理台先建 game 记录
  "version": "1.0.0",               // semver，必须递增
  "title": "极速反应",
  "engine": "canvas-native",        // phaser-4 | threejs | godot-4.6 | canvas-native（目录徽章展示，P5）
  "language": "typescript",
  "entry": "index.html",
  "cover": "cover.png",
  "size": {
    "totalBytes": 245000,           // 包总字节（校验器核对）
    "initialLoadBytes": 98000,      // 首屏必须拉取的最小集合（index.html + 关键 js），用于平台加载提示
    "maxAssetBytes": 200000000      // 单文件上限声明（校验器核对 ≤ 100MB）
  },
  "viewport": {
    "base": [960, 540],             // 设计基准分辨率（16:9）
    "scale": "fit",                 // fit | fixed
    "touch": true                   // 支持触控（移动端提示条用）
  },
  "score": {
    "enabled": true,
    "range": [0, 999999],           // 分数合法区间（平台校验链用，01 文档 §6.1）
    "unit": "分",
    "higherIsBetter": true,
    "metaSchema": {                 // 分数 meta 字段声明式 schema（平台校验用）
      "bestCombo": { "type": "int", "range": [0, 9999] }
    },
    "minPlayMs": 3000               // 有效提交的最短游戏时长（时间合理性校验）
  },
  "achievements": [                 // 成就定义（管理台亦可维护，发布时以包内为准并回写）
    { "code": "FIRST_WIN", "title": "首胜", "description": "完成一局",
      "rule": { "type": "game_over" }, "icon": "a1.svg" }
  ],
  "saves": {
    "localStoragePrefix": "reflexrush.", "maxBytes": 204800,   // 本地档（游客可用，M1 起）
    "cloud": { "enabled": true, "slots": ["default"], "saveSchema": { "maxBytes": 262144 } }  // 云存档（账号绑定，M3；01 文档 §5.2；saveSchema 可选，游戏自声明上限 ≤ 平台上限）
  },
  "audio": { "requiresGesture": true },   // 首次用户交互后开 AudioContext（自动播放策略提示）
  "notes": "技术拆解链接 / 已知限制（中文）"
}
```

### 3.2 包约束（校验器强制，见 §6）

| 项 | 约束 |
|---|---|
| 总大小 | ≤ 100MB（Godot 线程版 + 大音频也够） |
| 文件数 | ≤ 5000 |
| 允许扩展名 | `html js mjs css json wasm pck png jpg jpeg webp gif svg ico otf ttf woff woff2 mp3 ogg wav m4a xml txt map` —— **白名单制**，其他一律拒收 |
| 单文件 | ≤ 100MB |
| 入口 | 必须 `index.html` 在 `manifest.entry` 指定路径；HTML 内不得出现 `document.domain` 修改、
  `top.location` 跳转（静态规则扫描，§6.4） |
| `manifest.json` | schema 校验（json-schema，schema 文件随平台仓库版本化）；`size` 字段与实际核对（容差 0，必须一致——防「声明小实际大」） |

### 3.3 各引擎包的典型形态（对应 03..07）

| 游戏 | 包内容 | 典型体积 |
|---|---|---|
| D 极速反应 | index.html + main.js + 少量 css | < 100KB |
| A 霓虹突袭 | index.html + vendor(phaser)+bundle.js + 图集(atlas.json/png) + 音频(ogg) | ~4–6MB |
| B 方块狂奔 | index.html + three.bundle.js + bundle.js + glb(低模) + 音频 | ~8–15MB |
| C 地牢回声 | index.html + godot 引擎壳(js) + engine.wasm + game.pck + 音频(ogg) | ~25–35MB |
| E 弹珠对轰 | index.html + bundle.js + 音频 | ~2MB（逻辑重头在服务端） |

## 4. 播放器协议（平台 ⇄ 游戏）

### 4.1 postMessage 消息契约（targetOrigin 恒为 `location.origin`，游戏侧同约束）

| 方向 | 消息 | payload | 说明 |
|---|---|---|---|
| game → platform | `game:ready` | `{ version, engine, dpr, webgpu?: boolean }` | 游戏初始化完成（iframe 内首帧渲染后）；平台隐藏加载态 |
| game → platform | `game:error` | `{ code: "webgl-unavailable" \| "wasm-failed" \| "asset-404" \| "runtime", message }` | 平台显示错误卡 + 重试按钮；`wasm-failed` 时 Godot 游戏可提示「请升级浏览器」 |
| game → platform | `game:score` | `{ score, meta, clientTs }` | 请求提交分数（见 §4.3 鉴权） |
| game → platform | `game:track` | `{ type: "start"\|"end"\|"pv", durMs? }` | 遥测事件（M3 进 `play_session`） |
| platform → game | `platform:init` | `{ user: {id?, name?, anonymous}, session: {playSessionId, ts} }` | iframe 载入后由平台发送；游戏据此决定是否展示登录引导 |
| platform → game | `platform:restart` | `{}` | 「重新开始」按钮（玩家点平台侧按钮时） |

**规则**：① 所有消息 `e.source` 必须等于平台 iframe 引用（游戏侧同理）；② 消息体 ≤ 64KB；
③ 游戏对 `game:score` 的成功判定以平台响应为准（同源模式）或 `platform:score-result`（跨域模式）；
④ 平台 20s 未收到 `game:ready` → 超时 UI（重试 / 体积提示 / 浏览器建议）。

### 4.2 两种集成模式（同一游戏包都支持，M1 起默认模式一）

- **模式一：同源直连（MVP）**。游戏内
  `fetch('/game/api/scores', { method:'POST', headers:{'Authorization': `Bearer ${token}`}, body })`
  —— 简单、无消息中转；token 来源见 §4.3。
- **模式二：postMessage 代理（预留）**。游戏把请求发平台，平台前端代发（带 token）并回
  `platform:score-result`。用于游戏包迁 CDN 后。**M1 平台侧把两种都实现**（`GameFrame.vue` 内
  `scoreBridge` 模块 ~100 行），游戏 D 用模式一验证链路。

### 4.3 游戏如何拿到登录态（同源模式）

- 平台前端在 `platform:init` 前把中心 JWT 存入 `sessionStorage['gamevault.jwt']`
  （iframe 同源 ⇒ 共享 origin 的 sessionStorage 策略：**注意 sessionStorage 按 tab 按 origin 隔离，
  iframe 与顶层页同 origin 但 sessionStorage 不共享** ⇒ 改用 `localStorage['gamevault.session']`，
  同源 iframe 可读写，写前由平台校验该 key 未被污染（值必须与当前内存 token 一致才写；游戏读后只用于
  `Authorization` 头））。
- 游客（未登录）：`platform:init.user.anonymous=true`，游戏内分数入口显示「登录后保存」。
- ⚠️ JWT 进入 localStorage 的风险与对策：JWT 只用于同源 `/game/api` 调用（CORS 不开放其他 origin）；
  短 TTL（中心 30min 滚动）；管理台文档明示此为「便利通道」，M2 后若中心提供 per-game 短时凭据则切换。

### 4.4 存档（双轨：本地 + 云）

**本地档（localStorage，游客与登录玩家均可，M1 起）**：
- 每游戏前缀隔离（`manifest.saves.localStoragePrefix`），平台提供 `GameFrame.vue` 的「清空存档」按钮
  （调用 `platform:restart` 之外的 `platform:clearSave`，游戏侧监听后清自己前缀）。
- COEP 下 localStorage 行为不变（同 origin 照常）；跨源隔离不影响存储分区（Safari ITP 对第三方 cookie
  有限制，但 localStorage 同域不受影响——上线矩阵测试确认，01 文档 §10）。

**云存档（账号绑定、跨设备，M3 起；API 与表在 01 文档 §5.2/§3，仅登录用户）**：
- 内容存 `user_save` 表：对平台**不透明**（opaque JSON，平台不解析、不展示、不进任何公开 API），
  仅属主可读写（同 JWT）；≤256KB/槽、每用户每游戏 60 次/小时（Redis 限流）。
- 游戏侧流程（bridge 挂钩，~40 行，四款游戏同一份逻辑）：
  1. **启动**：已登录 → `GET /api/saves/<slug>` → 命中则用云档（并回写本地缓存）；404（首次）用本地档；
     游客 → 只用本地档。
  2. **存档点**（游戏自定义：过关/设置变更/每 30s 去抖）：先写本地（保证离线可玩），再 `PUT`（带 `baseUpdatedAt`）。
  3. **退出**（`pagehide`）：终值 `PUT`（best-effort；网络失败不丢——本地已安全）。
- 冲突语义（LWW-lite，无自动合并——opaque JSON 平台无法合并）：`PUT` 带 `baseUpdatedAt`，不一致 → 409，
  游戏弹「另一台设备有更新存档」：玩家选「用本地」（`force:true` 重 PUT）或「用云端」（重新 GET 覆盖本地缓存）。
- **首次登录不自动搬运**：云端空 + 本地有档 → 游戏可提示「上传本机存档？」，经玩家显式确认才 PUT
  （避免惊喜覆盖其他设备的旧档）。
- 版本迁移：游戏改存档结构 → `schemaVersion` +1，客户端读旧版迁移后 PUT 新版；服务端按 opaque 存储、不感知版本。
- 安全/隐私：JSON only（无 HTML/JS，无执行面）；尺寸/频率双闸；存档永不入榜单/遥测/管理台展示。

## 5. COOP / COEP / SharedArrayBuffer（本平台的「特色基建」）

**背景**：Godot 线程版（及任何想用 SAB 的游戏）要求文档处于「跨源隔离」状态，即响应必须带
`Cross-Origin-Opener-Policy: same-origin` + `Cross-Origin-Embedder-Policy: require-corp`
（Godot 4.6 官方文档《Exporting for the Web》明示，见 00 文档脚注 2）。

**本平台做法（一次配置，全游戏受益）**：
- nginx 在 `/game/` 与 `/game/g/` 两个 location 上统一加两头（01 文档 §8 片段已含）。
- 因为所有游戏资源都与页面**同源**，`require-corp` 自动满足（同源响应豁免 CORP 头要求）——
  **不需要给任何游戏资源加 `Cross-Origin-Resource-Policy` 头**。
- 影响面盘点（上线前逐项实测）：
  1. 顶层页 `/game/` 变跨源隔离 → `window.opener` 关系收紧（本平台无依赖，OK）；
  2. iframe 游戏内 SAB 可用（Godot 线程版跑通，M4 验收项：`window.crossOriginIsolated === true` 打印验证）；
  3. 外部嵌入我们页面的场景（无）；我们嵌外部资源（无，全部同源）⇒ 无破坏。
- **兄弟前缀隔离**：`/llm/`、`/EasyPCB/`、`/manage/` 的响应不带这两头（nginx location 作用域天然隔离，
  smoke.sh 抽样 `curl -sI` 三个前缀各 1 个 URL 断言无 COOP/COEP 头）。
- 兜底策略：若某浏览器在 COEP 下对同源 iframe 出现意外（上线矩阵测试发现），
  降级方案 = 该游戏只发**单线程构建**（Godot 4.3+ 单线程导出已修复完善，00 文档脚注 2），
  COOP/COEP 头保留（对单线程游戏无副作用）。

## 6. 发布管线（管理台 → 磁盘）

### 6.1 流程

```
上传 zip（≤100MB, multipart）
  → 建 game_version(staged) + 入 GAME_PACKAGE_PROCESS Job（Redis Streams，幂等键=packageId）
  → 消费者：
     ① 落盘暂存 /var/www/gamevault/staging/<packageId>/
     ② 校验（§6.2–6.4，任一失败 → staged+rejected，报告逐项列出）
     ③ 校验过 → 解压到 games/<slug>/<version>/（原子：先解到 .tmp 再 mv 改名）
     ④ 算 sha256 写库 → staged+ready
  → 管理员点「发布」→ 事务切 status：旧 live→rolled_back，新→live（目录不动，纯 DB 翻转 + 缓存失效）
  → 回滚 = 对 rolled_back 版本再点「发布」
```

- 大 zip（Godot 包 ~30MB）上传经 nginx `client_max_body_size 100m` 直通；Job 解压 ~30MB < 10s，
  但统一走异步（红线：长动作后台化），管理台轮询 `GET /api/admin/packages/{id}`（2s 间隔）。

### 6.2 结构校验

- 白名单扩展名（§3.2）；`manifest.json` 存在且过 json-schema；`size` 三值与实际一致；
  文件数 ≤ 5000；无 symlink / 硬链接 / 绝对路径条目 / `../` 穿越（zip slip 防护，逐条目检查
  `entry.getName()` 归一化后必须在包内）。

### 6.3 安全扫描（静态规则，非沙箱执行——红线：不运行上传代码）

| 规则 | 动作 |
|---|---|
| HTML/JS 中出现：`document.domain =`、`top.location`、`window.open('...','_top')` | **拒收** |
| JS 中出现内网地址特征（`10\.`、`192\.168\.`、`172\.(1[6-9]|2[0-9]|3[01])\.`、`169.254\.`、`localhost`） | **拒收**（防信息外泄/内网探测） |
| 密钥特征（`AKIA[0-9A-Z]{16}`、`-----BEGIN .* PRIVATE KEY-----`、`ghp_`、`xox[baprs]-`） | **拒收** |
| HTML `<meta http-equiv="refresh"` 指向站外 / `<form action="http` 站外 | **拒收** |
| 可疑大文件（>50MB 且扩展名与内容类型不符） | 标记人工复核（`needsReview`，发布按钮禁用直至管理台确认） |
- 全部规则命中即写报告（规则 id + 文件 + 行号），管理台可看；规则集版本化在平台仓库
  `src/main/resources/security/rules.json`，更新走代码评审。

### 6.4 发布后验证（自动）

发布动作触发一次「探针」：后端 `GET {entry_url}`（走 nginx 回环 `http://127.0.0.1/game/g/...`）
断言 200 + `content-type: text/html` + COOP/COEP 头在位；失败 → 自动回滚到上一 live + 告警日志。

## 7. 加载体验（玩家侧）

- 平台 `GameFrame.vue` 三态：`loading`（进度条 + 包体积提示「本游戏约 32MB，首次加载较慢」）→
  `ready` → `error`（按 `game:error.code` 给文案：wasm 失败 → 建议浏览器；asset-404 → 重试）。
- 进度条来源：同源模式下平台直接监听游戏关键资源（`index.html` 引用的 js/wasm）的
  `PerformanceObserver`/`fetch` 拦截不便时，退化为**游戏自报** `game:progress {pct}`（新增消息，
  Godot 包用引擎壳的 `statusbar` 回调转 postMessage，05 文档 §6 给出 Godot 侧实现）。
- Brotli：nginx `brotli on`（VPS 装 `libnginx-mod-http-brotli` 或换官方压缩模块），
  `wasm/js/json/html` 全压；Godot 官方也建议对 `.wasm` 用 gzip/brotli（压缩率 ~60%）。
- 长缓存：游戏版本目录 URL 天然带版本号（`/1.0.0/`）⇒ `expires 30d` 安全；`index.html`
  本身 `no-store`（由 `/game/g/` location 内嵌套 html location 单独加，避免整包 no-store 损失缓存）：

```nginx
# 细化：/game/g/ 下 HTML 禁缓存，其余资源长缓存（01 文档 §8 片段的最终形态）
location ^~ /game/g/ {
    alias /var/www/gamevault/games/;
    add_header Cross-Origin-Opener-Policy "same-origin" always;
    add_header Cross-Origin-Embedder-Policy "require-corp" always;
    location ~* \.html$ { add_header Cache-Control "no-store" always; try_files $uri =404; }
    location ~* \.(css|js|mjs|json|wasm|pck|png|jpg|jpeg|webp|gif|svg|otf|ttf|woff2?|mp3|ogg|wav|m4a|xml|txt|map)$ {
        expires 30d; add_header Cache-Control "public"; try_files $uri =404;
    }
}
```

## 8. 验收清单（每款游戏上线前过一遍）

- [ ] 管理台上传 → 校验报告全绿 → 发布 → 探针通过
