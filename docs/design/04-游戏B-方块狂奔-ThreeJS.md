## 1. 游戏设计

### 1.1 核心玩法

- 视角：第三人称后方斜 45° 跟随相机；玩家 = 发光方块（自转），在**三车道**悬浮轨道上自动向前。
- 操作极简（单手可玩）：**左右换道 + 跳跃**，无射击：
  - 桌面：`A/D` 或 `←/→` 换道，`空格/W/↑` 跳（可二段跳），`Shift` 滑铲（钻低栏）。
  - 移动：左滑/右滑换道，点按跳，下滑滑铲。
- 障碍类型（程序化生成，随距离提速）：
  1. **路障块**（占 1 道，跳/换道躲避）
  2. **激光栏**（低/高两档：低的必须跳，高的必须滑铲）
  3. **旋转锯**（横扫两道，节奏躲避）
  4. **能量门**（×2 得分 10s / 护盾 3s / 磁力吸金币 8s）
  5. **Boost 门**（穿过 → 2s 无敌 + 1.6× 速度爆发 + 路径金币自动吸入；800m 后出现）
  6. **节奏门**（本游戏核心新奇点，§1.5：按节拍时序判 FLOW；600m 后出现）
  7. **金币**（车道上成线/成弧；1% 概率出现**大金币** = 1,000 分）
- 失败 = 撞障碍（无护盾时），受击即连击倍率清零（§1.4）。单局无尽，距离（米）= 主分数。
- 每 500m 一个「检查点闪门」：穿过 = +5,000 分 + 短暂无敌（节奏喘息点）。
- 模式：`街机`（默认，含节奏门）+ `时间冲刺`（3 分钟内距离排名，M3 后开，§6）+ `Rhythm Rush`（v1.1：
  节奏门占比 40%，独立「节奏榜」，§6）。

### 1.2 计分

| 事件 | 分值 |
|---|---|
| 距离 | 1 分/米（×能量门倍率 ×连击倍率） |
| 金币 | 100 × 倍率（磁力模式下自动吸附） |
| 大金币 | 1,000 × 倍率 |
| 检查点 | 5,000 |
| 无伤通过 500m 段 | 2,000 |
| 近失擦过（§1.4） | +200 × 倍率 |
| Boost 门（2s 期间） | +100/0.1s + 路径金币 |
| FLOW（节奏门，§1.5） | PERFECT +1,000 且 ×2 持续 5s；GOOD +300 且 ×1.2 持续 5s |

`score.range` 0–99,999,999；meta：`{ meters, coins, checkpoints, maxSpeed, nearMisses, flowPerfect, mode: "arcade"|"rhythm" }`。
成就：FIRST_1K（1000m）、MAGNET_MASTER（磁力吸满 100 币）、NO_HIT_2K（2000m 无伤）。

### 1.3 视觉（2026-10-23「优」修订：不再「裸几何体」）

> 实现仍零资产文件（程序化几何 + Canvas 程序纹理 + emissive 材质，与 03 文档零资产路线一致）；
> 对标 = Subway Surfers / Temple Run 的画面完成度（来源 00 §3.4、§3.5）。

**玩家（从「自转方块」到「跑者」）**：
- 方块身体 + 正面 2 只「眼」（小亮色 quad）+ 顶部天线灯 → 独立剪影（背后 10m 也能认出）；
- **squash & stretch**：落地压扁（0.7×1.3）/ 空中拉长（1.1×0.9），0.15s 回弹；换道 = 身体倾斜 15°（bank）；
- **光轨**：身后 24 段渐隐 quad 链（长度 ∝ 速度），颜色 = 角色色；
- 尘土粒子：落地/换道 6–10 个（0.3s 消散）。

**障碍（每种独立材质 + 动效 + 预警示）**：
- 路障块：深色铁块 + **警示条纹**（Canvas 程序纹理，零文件）+ 品红边缘光脉冲（0.5s 周期）；
- 激光栏：2 发射节点（八面体）+ 之间能量束（细圆柱）——**点亮前 0.4s「闪烁」预警示**
  （公平性红线：障碍必须先可见可读、再致死，jjunior 2026-10-23 调研）；
- 旋转锯：**12 齿锯盘**（ExtrudeGeometry，弃「方块近似」）+ 高速自转 + 橙色边缘光；
- 门（能量/boost/节奏）：torus 环门 + 内圈符文环（30 段小 quad 反向旋转），类型色区分
  （×2=绿 / 护盾=青 / 磁力=金 / boost=红 / 节奏=紫）；
- 金币：旋转薄圆柱（r=0.12）；磁力激活时抛物线吸入；大金币 = 2× 尺寸 + 旋转辉光。

**环境（3 层视差 + 昼夜）**：
- 近层：楼宇 + **窗户灯点**（InstancedMesh 小 emissive quad，随机亮灭 + 偶发闪烁，1 draw call）；
- 中层：城市剪影（既有 InstancedMesh）；远景：山脊；
- 天空：顶点色渐变 + 星点 + 星云（既有）；**昼夜循环**：每 1000m 色调缓慢漂移
  （深蓝 → 紫 → 深橙），楼宇窗灯密度联动（夜更亮）；
- 轨道面：**发光网格纹理随速度滚动**（Canvas 程序网格，map.offset 滚动 = 提速即感）。

**速度感与「juice」**（GMT 游戏手感原则：重要事件 5–8 层微反馈、短促夸张、按事件量级缩放）：
- 速度线：屏幕边缘径向拉线粒子，密度 ∝ 速度；FOV punch：速度 30 → FOV 62→68；
- 屏震：撞击 0.1s / 检查点 0.15s / boost 门 0.2s；顿帧：大金币拾取 0.05s 冻结；
- 后处理：Bloom（r186 示例最简链路；FPS<40 自动关，§2.3 自适应）；像素比 3 档（min(DPR,2) / 1.5 / 1.0）。

**音频（WebAudio 运行时合成，零资产，实际实现 `audio/synth.ts`）**：
- BGM：1–2 首 cyber lo-fi，**固定 128 BPM 4/4，节拍时间线由 synth 导出为数据表**（§1.5 节奏系统数据源）；
  groove 模式叠加低音层（WebAudio gain 节点分层切换）；
- SFX：基础 5 条（换道/跳/金币/护盾/撞毁）+ 新增 3 条（近失「嗖」、FLOW 命中「叮」、boost「轰」）。

### 1.4 连击与近失（2026-10-23 新增；「优」玩法深度）

- **连击倍率**：连续「近失擦过 / 拾金币 / FLOW」累加 combo，倍率 ×1 → ×8（每次 +0.25，封顶），
  4s 无新累积 → 回落 ×1；受击 = 清零。倍率作用于金币/近失/距离得分。
- **近失擦过**：通过障碍时最近距离 < 0.35m 且未碰撞 → +200×倍率 + 「CLOSE!」飘字 +
  0.05s 顿帧 + 镜头轻微 zoom。奖励风险：同一障碍，越贴越高分（好 runner 的标准件）。
- HUD：左上 = 距离/得分；顶部中 = combo 条（×N + 衰减进度条）；飘字 = CLOSE! / FLOW / FLOW PERFECT。

### 1.5 节拍生成系统（2026-10-23 新增，本游戏核心「奇」点，用户 2026-10-23 暂准，实际效果演示后再最终确认）

**原理——「关卡即音乐」**：BGM 为运行时 WebAudio 合成（128 BPM、4/4），**节拍时间线完全已知**
（`synth.ts` 导出 `beatTimes[]` 表）。导演把障碍/门/金币的摆放**量化到节拍**
（`SpawnCmd.z = beatTime × speed`）：玩家跑起来自然跟拍，节奏从「装饰」变成「关卡结构」。

**节奏门（rhythm gate，紫色）**：按节拍穿过——
- |Δt| ≤ 90ms → **FLOW PERFECT**：+1,000 + 得分 ×2 持续 5s；
- |Δt| ≤ 180ms → **FLOW GOOD**：+300 + 得分 ×1.2 持续 5s；
- 偏离 = 普通通过（不惩罚；公平性：判定窗口在门环上可视化——正确时刻门环「收拢」，同 reflex-rush 圆环思路）。
- **Groove 模式**：连续 3 次 FLOW PERFECT → BGM 叠低音层 + 速度线增强 + 得分 ×1.5，直到受击中断。

**模式**：`街机`（默认：节奏门 600m 后出现，约每 400m 一扇）/ `Rhythm Rush`（v1.1：门占比 40%，独立榜，meta.mode=rhythm）。

**为什么是「奇」**（00 §3.4）：主流 runner 的关卡手设或纯随机，**「关卡数据与正在播放的 BGM 节拍时间线
同源」在主流中不存在**（2026-10-23 调研：同类新奇案例 = AVOID 90° 世界旋转 / Rule Runner 规则突变 / Run Into Puzzle
跑酷×解谜，均无音乐生成关卡）；且它是本平台零资产/合成 BGM 技术路线的自然延伸（beatmap = 关卡数据），
技术拆解页 P5 的核心叙事素材。

**工程**：节拍表 = 纯数据表；Δt 判定纯函数（可单测，边界表形状同 reflex-rush `judge.ts`）；
低端机（quality=low）节奏门**自动降级为「只通过不判定」**（不产生不公平）。

## 2. 技术选型与工程结构

### 2.1 选型裁定

- **Three.js r186（2026-09 发布）**：`WebGPURenderer` 为官方「WebGLRenderer 的现代替代」，
  **默认尝试 WebGPU，不支持时自动回退 WebGL2 后端**（官方文档，00 文档脚注 1）——一份代码两档画质，
  正是本平台要的「WebGPU 展示 + 全环境可玩」。
- 不用 TSL（节点着色语言）写材质——r186 标准 `MeshStandardMaterial`/`MeshBasicMaterial` + emissive
  足够本游戏视觉量级；Bloom 走 r186 examples 的 webgpu 后处理链路（以当前版本示例为准，红线：官方当版本）。
- **不用物理引擎**：跑酷只需要「车道插值 + 抛物线跳 + AABB 碰撞」，手写 ~200 行，比引入
  rapier/cannon 省 1MB+ 且帧率更稳。
- 资源格式：模型 `.glb`（Blender 低模导出，<100KB 全部模型）+ 音频 ogg；无纹理图集（纯色 + emissive）。
- TypeScript + Vite；three 走 npm（~700KB min，gzip ~170KB）。

### 2.2 工程结构

```
games/cube-rush/
├── package.json            # three@r186, typescript, vite
├── vite.config.ts
├── index.html              # 入口：canvas + 加载条 + WebGPU 检测提示
├── manifest.json           # engine: "threejs"（卡片徽章：Three.js · WebGPU）
└── src/
    ├── main.ts             # 启动：检测 webgpu → new WebGPURenderer()（回退逻辑内建）→ 场景装配
    ├── game/
    │   ├── Game.ts         # 主状态机：menu | running | paused | result（rAF 循环 + 固定步长 60Hz 逻辑）
    │   ├── track.ts        # 轨道分块生成器（前 4 块后 1 块，复用 BufferGeometry；障碍按距离表放置）
    │   ├── player.ts       # 方块 + 换道插值（easeOut 0.15s）+ 跳（二段）+ 滑铲 + AABB 碰撞
    │   ├── camera.ts       # 跟随 + 轻微 lag + 撞击镜头抖
    │   ├── obstacles.ts    # 5 类障碍工厂 + 生成导演（随 meters 的难度曲线，数据表驱动）
    │   ├── collectibles.ts # 金币/能量门（磁力吸附 = 目标点插值）
    │   └── environment.ts  # 星云/远景/灯光（3 点光 + hemi，全部静态烘焙进材质）
    ├── render/
    │   ├── setup.ts        # WebGPURenderer 创建 + 失败时 WebGL2 回退日志（game:track 报 webgpu:false）
    │   ├── post.ts         # Bloom（按帧预算开关：FPS<40 自动关 Bloom）
    │   └── adaptive.ts     # 像素比/粒子/Bloom 三档自适应（0.5s 滑动窗口 FPS 决策）
    ├── input/
    │   └── input.ts        # 键盘 + 触控（swipe 判定 30px 阈值）统一成 Command
    ├── audio/audio.ts      # WebAudio（首交互初始化，02 文档 §4）
    ├── platform/bridge.ts  # games/shared/bridge.ts 同款（02 文档 §4）

```

**新增/变更模块（2026-10-23 修订）**：`audio/synth.ts` +节拍时间线导出 + groove 低音层；`core/director.ts`
 +节拍量化；`core/scoring.ts` +连击/近失/FLOW；`game/track.ts` +boost/节奏门类型 +窗灯；`game/player.ts`

### 2.3 关键实现要点

- **轨道生成**：`track.ts` 维护 4 个 100m 块；玩家前进 50m 时最远块重排（障碍/金币重掷，
  用 `seed + blockIndex` 确定性随机，重开同距离布局可复现，利于调平与测试）。
- **碰撞**：玩家 AABB（0.8³）vs 障碍 AABB（每块预计算，随块移动）；金币用距离阈值（0.6m 吸附）。
  逻辑固定 60Hz 步长，渲染 rAF 解耦（渲染帧内最多补 3 个逻辑步，防螺旋死亡）。
- **Draw call 预算 ≤ 50**：远景城市 `InstancedMesh`（1 draw call，500 实例）；金币 `InstancedMesh`
  （同材质合并）；轨道块 4 draw call；障碍 ≤ 24 独立 mesh（材质各 1）。
- **WebGPU 检测与展示**：`navigator.gpu` 存在 → 尝试 `WebGPURenderer`；成功在结算页显示
  「WebGPU ✓」徽章，失败回退 WebGL2 显示「WebGL2 兼容模式」——**把回退本身做成展示内容**
  （技术拆解页 P5 的素材），`game:ready` 里带 `webgpu: boolean` 遥测上报，平台统计「WebGPU 占比」。
- **提分链路**：`Result` 页 → `bridge.submitScore(meters×1+coins×100+..., meta)`，同 03 文档 §2.3。

## 3. 性能预算

| 项 | 目标 |
|---|---|
| 包体积 | ≤ 15MB（three ~170KB gz + 代码 ~150KB gz + glb 全集 ≤ 1MB + 音频 ≤ 2MB；余量给后处理 chunk） |
| 首玩时间 | 4G P90 ≤ 8s；WebGPU 编译首次 +2s（引擎 shader 预热，加载条覆盖） |
| 帧率 | 桌面 WebGPU 60fps；WebGL2 回退 50fps 可玩；移动端：关 Bloom + 像素比 1.0 → 45fps |
| Draw call | ≤ 64（窗灯/光轨/金币各走 InstancedMesh 合并批次；较原预算 +14，见 §1.3） |
| 粒子 | 总预算 ≤ 256（光轨 24 / 尘土 64 / 速度线 32 / 金币与命中 96 / 余量 40；低档减半） |
| 内存 | 峰值 ≤ 350MB（WebGPU 资源池，关卡内不增长——块复用的关键验收项） |

## 6. v1.1 演进（M3 后，2026-10-23 新增，按 00 文档 §3.4）

1. **幽灵竞速（奇点②，已暂准）**——runner 品类的「与王同跑」：
   - 录制：局内操作（换道/跳/滑铲事件，10Hz delta 编码 + base64，典型 1–4KB）；
   - 存储：本地 localStorage（立即可玩）+ 云存档上传（01 文档 §5.2 M3 云存档 API，slot=ghost-best）；
   - 对手选择：「与自己的最好纪录跑」→「与榜一跑」（平台取总榜第一分数的 meta 作幽灵，
     平台只需加小只读端点 `GET /api/games/{slug}/leaderboard?top=1&withMeta=true`）；
   - 渲染：幽灵 = 半透明方块（emissive 0.2）+ **同种子轨道**（既有确定性生成天然兼容，seed = 榜首分数行 id）；
   - 为什么是「奇」：同轨幽灵竞速是竞速品类标准件、**runner 品类罕见**，且由本平台三件既有能力
     （排行榜 + 云存档 + 确定性轨道）**原生拼出**——别家平台抄不走。
2. **角色三件套（成就解锁）**：① 冲刺立方（Shift/双触 0.4s 冲刺，每局 2 次）② 相位立方（每局可穿过一次低激光栏 +
   滑铲时长 +50%）③ 磁力立方（开局 5s 自动磁力）；每角色独立配色/纹样（emissive 图案）/光轨色；菜单加角色选择。
3. **时间冲刺模式**：3 分钟内距离排名（原 §1.1 设计），复用引擎 + 同一导演，独立榜单。
4. **波形图案表**：纯权重表 → 10 种图案（之字/锯走廊/激光雨/金币拱/检查点冲刺……），
   30s「紧张–放松」循环（30s 密集 → 15s 放松 + 必出能量门）。
5. **皮肤系统**：配色/纹样/光轨色，按榜单位次解锁。
